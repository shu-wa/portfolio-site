# 飲食店注文・在庫管理システムの掲載

大学の「プロジェクト演習12」で4人チームで制作したCLIアプリです。最終提出コード・設計図・本人の最終レポートを確認し、設計、Main、価格/カロリー検索、限定表示、各クラスの統合を担当範囲として記載しました。チーム制作後の個人拡張であるメニュー登録も分けて説明しています。

公開コードは https://github.com/shu-wa/restaurant-order-system です。本人からチームソースの公開許可があることを確認しています。元フォルダは編集せず、講義教材、他のメンバーの個人情報、旧DB設定、元CSVは公開版へ含めていません。

保守改修は授業当時の成果と区別します。作品ページの「授業後の保守改修」「保守版の設計」「保守版の実行結果」は今回の見直しです。根拠を確認できなかった旧紹介文の「NOT INで問題が起こりNOT EXISTSへ変更した」という経緯は削除しました。

## 公開データ

`data/restaurant-order-system.json`が紹介用の原稿兼、管理画面から取り込めるJSONです。ソース改訂日時よりDB登録が古い場合だけ、確認済みの原稿を一覧・詳細・公開APIに適用します。その後の管理画面での更新は優先し、保存データそのものを上書きしません。

公開処理は`lib/restaurant-publication.ts`、データ取得は`lib/projects.ts`に集約しています。作品を完全に掲載停止する場合は、このJSONの参照と公開補完処理も外してください。

`public/images/restaurant-order-system/`の2枚は、Javaのテストで得た実行ログから、プロンプトを省いて画像化したものです。架空データであることと、保守版のログ抜粋であることを画像内に明記しています。Webアプリの画面や実店舗での運用実績としては扱いません。

## 検証

- Javaの34テストをH2とGitHub Actionsの使い捨てMySQL 8.4で実行。
- サイトのセキュリティ回帰テストに、古いDB登録の差し替え・後日の管理編集の優先・一覧と詳細の一致を追加。
- `scripts/check-restaurant-work.mjs`で1440/768/320px幅の詳細ページ、画像の比率・読込、GitHubリンク、公開API、アクセシビリティとTSUDOWA非公開情報の維持を確認。

本CLIは学習用であり、本番サービスの認可・決済・監査・障害復旧を実装済みと説明しないでください。詳しい制約は公開リポジトリのREADMEとSECURITYに記載しています。
