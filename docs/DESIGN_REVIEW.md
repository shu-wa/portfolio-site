# Design Review

## コンセプト

「とりあえずなんでもやってみる！！」。AIを道具として使いながら、小さく試し、理解し、育てる姿勢を中心にしました。制作物はスキルの羅列ではなく、好奇心の記録として構成しています。

トップ、制作物一覧、制作物詳細、自己紹介、お問い合わせ、モバイルメニューを同じデザインへ更新しました。余白のある編集的な構成、ライムと赤のアクセントを使い、制作物と人物像を分かりやすく伝えます。

## 2026-10-03: 触れる好奇心

分かりやすい見出しと制作物への入口を維持し、制作モードの切り替えを復活させました。単なる文言変更ではなく、背景色・操作デモ・作品の分類が連動します。初期状態は全作品を表示し、制作モードを選ぶと対応する分類へ切り替わります。

- アプリ: アイデアメモ。追加・完了・未完了への戻し・削除・絞り込みができ、このブラウザのlocalStorageへ保存します。作品登録や外部への送信は行いません。
- ゲーム: [Matter.js](https://brm.io/matter-js/docs/classes/Engine.html) を使った物理パーツ。ドラッグ、跳ねる、重力反転、リセットを用意。ライブラリはこのモードを選ぶまで読み込みません。
- 仕組み: タイトルを整え、アイデアのJSONを生成・ダウンロードするローカル処理。実際の作品登録や公開処理は行いません。
- 作品一覧: 分類フィルターと制作モードを同期。シャッフルでは作品を消さずに表示順だけを変更します。

デモの領域を固定し、外枠を付けず背景と一体の見せ方にしました。音や物理動作の自動再生はありません。物理動作は画面外・非表示タブでは止まり、通常は操作後4秒、Reduced Motionでは650msで停止します。モードを離れるとエンジンとイベントを破棄します。

検証で見つけたJSON欄のキーボードフォーカス不足と、320px幅でデモ領域が下のリンクへ近づく問題を修正しました。ブラウザ検査ではメモの操作と保存、3モードの循環、分類同期、Canvasのピクセルと動作・ドラッグ、JSONの内容とダウンロード、シャッフル後の作品保持、デモの収まりを確認します。通常の動きとキーボード操作、処理途中のモード切り替えも対象です。

## 2026-10-04: アプリの実用性と短い画面の配置

参加人数だけを変える試作から、実際に使える小さなメモアプリへ変更しました。追加したメモは先頭に表示します。最大12件・各48文字とし、保存データの型・件数・IDの重複を検証します。保存が無効な環境では、そのページ内の一時保存へ切り替え、状態メッセージでも区別します。別タブからの変更にも追従します。

390x740と430x740でJSONの完了メッセージとヒーロー下部の文章の重なりを再現しました。モバイルでは下部を固定位置から通常の縦並びへ移し、各デモはメッセージ用の行を常に確保します。低い画面では余白と操作部をコンパクトにし、375x667を含めた検査を追加しました。処理中・完了・入力エラーのいずれもデモ内に収まることを確認する回帰検査を設けています。

## 品質目標

[Webbyの公式審査基準](https://www.webbyawards.com/judging-criteria/) の内容、構造・ナビゲーション、視覚、機能、インタラクション、革新性、全体体験、および [Awwwardsのモバイル品質ガイド](https://www.awwwards.com/mobile-excellence-guidelines.pdf) をチェックの観点にしました。FWAのような体験性の高いサイトも目標にしていますが、受賞水準の認定や受賞の保証はできません。

## セルフチェックと改善

- 初稿: 新しいレイアウト、メディア表示、分類フィルター、ネイティブdialogメニュー、Web Audio、フォーム状態を実装。
- 第1回: PCのヘッダーのコントラスト、スマホで背景が見えない配置、一覧の端末画像の見切れを修正。写真の比率を維持し、タッチ領域を拡大。
- 第2回: axe-coreで見つかったコード風ビジュアルの文字色の競合を修正。タブレットの作品一覧を1列へ切り替え、端末画像の見切れを解消。
- 第3回: 320px幅でコード風ビジュアルが下のラベルへ近づく問題を修正。TSUDOWAの詳細画像に元の寸法を指定し、遅延読み込みでも表示領域を確保。
- 第4回: ファーストビューで名前が明確に認識できるサイズへ変更し、最小幅の余白を調整。
- 分かりやすさの見直し: 文言だけを切り替えるリロードボタンとギターの体験を削除。日本語のメニューと明確なセクション見出し、トップのポートフォリオ紹介、制作物へのリンク、フッターの管理者ログインを追加。
- 自動検証: 1440x1000、1920x1080、768x1024、390x844、320x740。横方向のはみ出し、読み込み画像、端末画像の収まり、画像の元の比率、メニュー最前面、Escape、フィルター、画面遷移、制作物へのリンク、管理者リンク、フォーム成功状態、CSP、JavaScriptエラー、WCAGの自動検査を確認。
- 動き: Reduced Motionを尊重します。止められない無限のスクロールアニメーションは採用していません。

問い合わせのブラウザテストは通信をモック化し、本番へのテスト問い合わせは送りません。自動アクセシビリティ検査だけでは、スクリーンリーダー・実機の全体体験を保証しません。

2026-10-04のローカル検査では、8種類の画面サイズで横方向のはみ出し、CSP違反、JavaScriptエラー、axe-coreの対象WCAG違反が0件でした。観測した初期CLSは0でした。通常の動きはPCと高さ740px・667pxのスマホで処理中・完了・途中離脱を確認しました。これはローカルの検証値であり、本番の利用者データやLighthouse認定スコアではありません。

## ビジュアル素材

ヒーローの背景は組み込みの画像生成機能で作成し、WebPへ最適化しました。最終素材は `public/curiosity-workbench.webp`、1536x1024、約75KBです。人物写真とTSUDOWAの画面は既存素材です。作品にスクリーンショットがない場合の図形・コード表現は、実際のスクリーンショットと偽って扱いません。

生成プロンプトの要旨: 明るい淡いグレーの作業台を真上から撮影した編集的な写真。左側58%は見出しのために空ける。右側に黒いゲームコントローラー、ライム色のキーキャップ、赤いギターピック、小さな回路、青いプリズム、銀のばね、鉛筆。文字・ロゴなし。自然な明るい光と現実的な影。横長の高精細な構図。

## 再現方法

```powershell
npm ci
npm run test:security
npm run lint
npm run build
$env:SITE_ORIGIN='http://localhost:3100'
npm run start -- -p 3100
# 別のターミナルで実行。Chromeを使用。
npm run test:browser
```

スクリーンショットと検査結果は `.artifacts/browser` に出力され、Gitへは含めません。公開先の確認は `TEST_BASE_URL` に公開URLを指定して実行できます。

幅を限定して再検査する場合は、例えば `$env:TEST_WIDTH='320'` を設定します。全サイズの検査ではこの変数を解除してください。

保存まわりだけを再検査する場合は `$env:TEST_SCOPE='notes'` を設定します。再読み込み後のメモと空状態、別タブのメモは、HTMLの初期表示ではなくクライアントへの反映を待って判定します。通常の検査ではこの変数を解除してください。
